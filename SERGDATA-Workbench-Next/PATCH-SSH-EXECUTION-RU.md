# SERGDATA Workbench — SSH / Execution patch (этап 1)

## Что добавлено

- Инструмент `ssh_read_file`: чтение удалённого файла по SSH.
- Инструмент `ssh_run_command`: постановка удалённой команды в существующую очередь подтверждения.
- Используется системный OpenSSH (`ssh`), без хранения паролей и приватных ключей в Workbench.
- Включены `BatchMode=yes`, `PasswordAuthentication=no`, `StrictHostKeyChecking=yes`, таймаут соединения и keepalive.
- Вывод ограничен по размеру; stdout/stderr и exit code разделены.
- Чтение ряда очевидных секретных путей/типов файлов запрещено.
- В панели подтверждения отображается человекочитаемая SSH-команда.
- Типовые проверки проекта возвращают модели статус, настоящий exit code, stdout и stderr.
- Локальный PowerShell на Windows получил обработку terminating errors и попытку сохранить ненулевой код нативной команды.

## Предварительные условия SSH

1. На Windows должен быть установлен OpenSSH Client (`ssh.exe`) и доступен в PATH.
2. На сервере должна быть настроена ключевая аутентификация для нужного пользователя.
3. Ключ должен быть загружен в Windows `ssh-agent` либо доступен стандартному OpenSSH.
4. Host key сервера должен быть заранее и независимо проверен и добавлен в `known_hosts`. Workbench не отключает проверку ключа и не принимает неизвестный host key автоматически.
5. Для первого теста используйте отдельного пользователя с минимальными правами, если это возможно.

Пример ручной проверки подключения из PowerShell:

```powershell
ssh -p 2222 root@fin.sergdata.top
```

Не принимайте новый host key вслепую: сверяйте fingerprint с консолью VPS или доверенным каналом.

## Как модель использует инструменты

Для чтения:

- `ssh_read_file(host, user, port, path)` — только чтение абсолютного пути.

Для команд:

- `ssh_run_command(host, user, port, command)` — создаёт запись в очереди.
- Команда не запускается до явного нажатия «Выполнить» в панели.

## Ограничения этапа 1

- Пока нет отдельного менеджера профилей серверов.
- Пока нет выделенных инструментов SCP/SFTP, удалённой записи файлов и резервного восстановления файлов.
- Нет реального интеграционного теста с `fin.sergdata.top`: он требует корректного SSH-ключа и проверенного host key на компьютере пользователя.
- Произвольная команда после подтверждения выполняется shell'ом удалённого пользователя. Перед нажатием «Выполнить» внимательно проверяйте команду.
- Чтение файлов ограничено защитой по типовым именам секретов, но это не полноценная система классификации секретных данных. Не предоставляйте агенту root-доступ без необходимости.
