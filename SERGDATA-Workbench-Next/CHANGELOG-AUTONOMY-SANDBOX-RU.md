# Изменения автономности Sandbox — 2026-11-05

## Что изменено
- Добавлен режим `mode=empty` для `sandbox_create`: создаётся отдельная пустая рабочая область без копирования активного проекта.
- `mode=copy` сохранён как режим совместимости и продолжает копировать проект/выбранные файлы.
- При ошибке создания рабочей области частично созданная папка удаляется.
- Выбранные пути проверяются до разрешения (`resolve`): запрещены абсолютные пути, `..`, пустые компоненты и symlink-компоненты.
- Diff для `empty`-областей показывает только добавленные/изменённые файлы и не считает весь исходный проект удалённым.
- Агенту явно предписано вести задачу внутри Sandbox через sandbox_* инструменты, не переходить на `write_project_file`, самостоятельно выполнять разрешённые внутренние записи и останавливаться перед переносом.
- Политика автономности уточнена: `analysis` требует подтверждения для изменений основного проекта, но не для записей внутри отдельной Sandbox после поручения автономной задачи.

## Ограничения и безопасность
- Это файловая рабочая область, НЕ изоляция ОС.
- `pytest` исполняет тестовый Python-код на хосте; `compile` тоже запускает интерпретатор на хосте.
- Нельзя считать Runner безопасным для произвольного/недоверенного кода. Для настоящей изоляции нужен отдельный Windows execution backend (например, Windows Sandbox/Hyper-V/контейнер с жёсткими ограничениями), контроль процессов, сети, томов и времени.
- Windows-специфичные проверки, реальный Workbench UI, LM Studio, SSH Engine и Release Manager не тестировались в Linux-контейнере.
- Исходная папка пользователя и GitHub не изменялись; работа сделана только в отдельной распакованной тестовой копии.
