# SERGDATA Workbench — универсальный защищённый ввод и SSH-профили

Дата сборки: 03.11.2026

## Что добавлено

- `request_user_input` — обычный ввод через отдельную панель.
- `request_user_secret` — секретный ввод через password-поле. Секрет не передаётся модели.
- `CredentialBroker` — временные секреты в памяти; постоянные секреты на Windows защищаются DPAPI CurrentUser в `.workbench/credentials.dpapi`.
- `create_server_profile`, `update_server_profile`, `list_server_profiles` — управление SSH-профилями без передачи паролей в tool arguments.
- `ssh_run_profile_command` — SSH-команда через выбранный профиль с обязательным подтверждением в панели.
- Парольная SSH-аутентификация через Paramiko; неизвестные host keys отклоняются `RejectPolicy`, автоматическое принятие запрещено.
- Общая политика блокировки секретных файлов для project tools, execution tools, SSH file reader и ZIP-вложений. Дополнительно закрыты `password/passwd/passphrase`, `*.env`, `.pgpass`, `.my.cnf`, `.htpasswd`, `auth.json`, cookies/session-файлы, нестандартные имена `id_*`, `.ppk` и `.ovpn`.
- Автоматическое продолжение исходного tool-call после ввода; batch tool calls сохраняются с placeholder для ожидаемого вызова и заблокированными результатами невыполненных sibling calls.
- Атомарный claim для resume и finish execution.
- Результат процесса сохраняется callback-ом независимо от открытой вкладки; GET-поллинг — дополнительный fallback.
- При остановке Workbench процессы получают отмену; если процесс был оборван перезапуском, автоматический повтор запрещён.
- Реестр процессов ограничивает хранение завершённых записей последними 100 задачами; активные процессы не удаляются. Результаты операций предварительно сохраняются в SQLite.
- Завершённые результаты, которые ещё не продолжили диалог, возобновляются при следующем старте.
- Локальный API принимает только loopback Host и блокирует cross-origin/cross-site запросы.

## Установка поверх существующего проекта

1. Останови Workbench.
2. Сделай резервную копию каталога проекта и `.workbench/workbench.sqlite3`.
3. Сохрани собственные `.env`, `.workbench`, `projects`, пользовательские файлы, SSH `known_hosts` и существующий `migration/legacy-workbench.sqlite3` (если он есть).
4. Распакуй обновлённые исходники поверх каталога `SERGDATA-Workbench-Next` с заменой файлов.
5. Не заменяй `.env` и `.workbench` файлами из архива.
6. Запусти `start.cmd`; установщик обновит зависимости из `requirements.txt`, включая `paramiko`.
7. Убедись, что `doctor` показывает Paramiko как установленный модуль.

SQLite мигрируется автоматически. Проверено на копии базы из исходного архива: все 18 существовавших таблиц сохранили точное количество строк; добавлены `input_requests` и `server_profiles`.

## Использование

- Для обычного значения модель вызывает `request_user_input`.
- Для пароля, PIN, OTP, passphrase, API-токена или секретной фразы модель вызывает `request_user_secret`.
- Пользователь вводит значение в отдельной панели. Не отправляй секрет обычным сообщением чата.
- Для парольного SSH-профиля модель может запросить секрет, затем создать профиль через `create_server_profile` либо обновить его через `update_server_profile`.
- Пользователь может создать профиль вручную в панели SSH-профилей. Парольное поле отправляется отдельным POST и не возвращается API.
- Перед первым SSH-подключением проверь fingerprint сервера и добавь host key в `~/.ssh/known_hosts`. Не отключай проверку ключей.
- Команды SSH выполняются только после нажатия «Выполнить» в панели.

## Ограничения и честные замечания

- Постоянное сохранение через DPAPI доступно только на Windows и привязано к текущей Windows-учётной записи. На других ОС доступен временный режим; секрет исчезает при перезапуске.
- Реальное подключение к FIN/SUB из среды сборки не выполнялось: не было доступа к пользовательским SSH-ключам, паролям и проверенной серверной среде. Парольный адаптер проверен модульными тестами с имитацией Paramiko и обязательной RejectPolicy.
- После установки проверь соединение с каждым профилем безопасной командой `hostname`, внимательно сверив хост и fingerprint.
- Если Workbench перезапускается во время команды, результат помечается как неизвестный. Сначала проверь состояние на сервере, только затем создавай новую команду.
- Удалённый bind (`HOST=0.0.0.0`) намеренно запрещён в этой сборке. Для удалённого доступа нужна отдельная аутентифицированная архитектура.
