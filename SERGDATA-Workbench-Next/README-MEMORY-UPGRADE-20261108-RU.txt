SERGDATA Workbench — патч улучшения памяти
Дата: 08.11.2026
Основа: SERGDATA-Workbench-Next(test)(5).zip

ЧТО ИЗМЕНЕНО
1. Настройка «Максимум символов одного сообщения при суммаризации» в разделе «Настройки агента».
   - Значение по умолчанию: 15000 символов.
   - Диапазон: 1000–50000.
   - Хранится в SQLite app_settings и применяется без перезапуска к следующему запросу.
   - Если сообщение длиннее лимита, в текст сводки добавляется явная отметка с фактической длиной и указанием, что передано только начало. Обрезка больше не происходит молча.
2. Суммаризация получает структурированный формат с разделами: цель/состояние, подтверждённые факты, архитектура/пути, решения/причины, ограничения/непроверенное, ошибки/проверки, следующие шаги.
3. Каждая новая отличающаяся версия памяти ветки сохраняется в memory_snapshots до обновления текущей сводки. Это позволяет искать старые сведения, которые модель могла исключить из новой сводки.
4. Добавлен поиск по текущей памяти веток, сохранённым снимкам, памяти задач и памяти проектов. Поиск лексический (по словам), не семантический.
5. Runtime-сжатие сохраняет системные инструкции и добавляет временную сводку в то же system-сообщение, а не создаёт второе system-сообщение. Это снижает риск несовместимости с chat templates LM Studio.

БЕЗОПАСНОСТЬ ДАННЫХ
- Патч не содержит пользовательскую SQLite-базу, .git, .env, credentials или проектные данные.
- Новая таблица создаётся штатным CREATE TABLE IF NOT EXISTS при старте Store.
- Текущие таблицы и строки не перезаписываются миграцией.
- Перед установкой всё равно сделайте резервную копию папки .workbench целиком.

УСТАНОВКА
1. Полностью остановить SERGDATA Workbench.
2. Сделать копию папки .workbench (в ней SQLite и учётные данные) и, желательно, всей папки приложения.
3. Распаковать архив поверх корня SERGDATA-Workbench-Next с заменой файлов, сохраняя структуру каталогов.
4. Запустить Workbench.
5. Открыть «Настройки агента»: появится поле лимита символов суммаризации, значение по умолчанию 15000.

ОТКАТ
1. Остановить Workbench.
2. Вернуть файлы из резервной копии приложения.
3. Если нужно полностью вернуть БД к прежнему состоянию — восстановить резервную копию .workbench целиком. Таблица memory_snapshots безвредна для старого кода, но для полного отката БД используйте именно резервную копию.

ПРОВЕРКИ В СРЕДЕ СБОРКИ
- Целевые тесты памяти, настроек и runtime-сжатия: 10 passed.
- Python compileall: успешно.
- Node.js --check static/app.js: успешно.
- Проверка миграции на копии SQLite из архива: количество projects/tasks/branches/messages/branch_memory до и после совпало (8/15/15/703/8); настройка по умолчанию вернулась как 15000.

ОГРАНИЧЕНИЯ
- Поиск сейчас лексический, а не embedding/semantic.
- Структура фактов задаётся разделами сводки и сохранением версий; отдельная нормализованная таблица атомарных фактов с оценкой достоверности в этом патче не вводится.
- Проверка реальной суммаризации на локальной модели LM Studio не выполнялась: тесты используют изолированную логику и не подключаются к пользовательскому LM Studio.
