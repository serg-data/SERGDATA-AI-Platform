# SERGDATA Workbench — SSH execution/resume patch

## Что исправлено

1. Pending execution теперь может хранить снимок OpenAI-compatible messages, исходный `tool_call_id`, модель и исходное user-message ID.
2. После завершения процесса `GET /api/processes/{job_id}` сохраняет stdout/stderr/exit code и запускает `Agent.resume_execution()`.
3. Результат передаётся модели как `role=tool` с исходным `tool_call_id`; модель получает возможность продолжить цикл и вызвать следующие инструменты.
4. Продолжение ограничено настройками Workbench по числу раундов/инструментов и использует текущую компактизацию контекста.
5. Отказ пользователя также возвращается в исходный tool-call цикл как отказ, чтобы модель могла продолжить без выполнения команды.
6. Повторное нажатие «Выполнить» не запускает один запрос дважды: строка атомарно переводится `pending → running`.
7. SSH через `execute_powershell` блокируется на уровне инструмента. Старые ожидающие PowerShell-команды, содержащие SSH-вызовы или серверы `*.sergdata.top`, блокируются также на API подтверждения.
8. После завершения процесса UI обновляет историю и очередь команд. Текстовое «подтверждаю» в чате не заменяет реальное нажатие кнопки в панели выполнения.
9. Добавлены миграционные поля к `pending_execution`. Существующие записи и история не удаляются.

## Установка

1. Останови Workbench.
2. Сделай резервные копии файлов, которые будут заменены:

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
New-Item -ItemType Directory -Force ".backup-$stamp" | Out-Null
Copy-Item main.py ".backup-$stamp\main.py"
Copy-Item workbench\agent.py ".backup-$stamp\agent.py"
Copy-Item workbench\db.py ".backup-$stamp\db.py"
Copy-Item static\app.js ".backup-$stamp\app.js"
```

3. Распакуй содержимое ZIP в корень существующего `SERGDATA-Workbench-Next`, согласившись на замену четырёх файлов.
4. **Не заменяй и не удаляй** `.env`, `.workbench`, `workbench.sqlite3`, папки проектов, ключи SSH и `known_hosts`.
5. Запусти Workbench через `start.cmd`.
6. В панели выполнения отклони старый запрос ID=10, созданный прежней версией как PowerShell-обёртка SSH. Не нажимай для него «Выполнить»: новый API намеренно блокирует этот обход.
7. Отправь новый запрос на диагностику FIN. Убедись, что модель вызывает `ssh_run_command`, а в панели появился запрос типа SSH. Нажми именно кнопку «Выполнить».
8. Дождись завершения процесса. В панели появятся stdout/stderr и exit code; после этого Workbench должен автоматически добавить ответ модели в историю.

## Ограничения этого патча

- SSH-ключ FIN работает через системный OpenSSH и Windows `ssh-agent`; это тот режим, который был проверен вручную.
- SUB с парольной авторизацией этим патчем ещё не подключён к защищённому хранилищу Windows. Не включай передачу пароля через аргументы командной строки, `.env`, SQLite или сообщения модели. Для SUB нужен отдельный credential-provider/профиль (Windows Credential Manager/DPAPI) и отдельная проверка.
- Уже созданная до патча запись ID=10 не имеет исходного tool-call контекста. Её нужно отклонить и создать новый запрос после установки.
