# SERGDATA Workbench — исправление LM Studio HTTP 400 при наличии checkpoint

Версия: v1.2.1
База патча: SERGDATA-Workbench-Execution-Continuity-v1.2

## Что исправлено

1. Контрольная сводка больше не добавляется отдельным `system`-сообщением в середину истории диалога.
   `_context_messages()` формирует один ведущий `system`-prompt. Теперь checkpoint briefing объединяется с его содержимым.
   Это устраняет некорректную последовательность ролей, которую некоторые chat templates LM Studio отклоняют HTTP 400.
2. Диагностика HTTP 400 получила fallback на безопасное сообщение исключения SDK, если `body`/`response.text` пусты.
   Запрос пользователя, сообщения, аргументы инструментов и заголовки не логируются; строка ошибки ограничена 800 символами и проходит редактирование типичных секретов.

## Что намеренно не менялось

- `_prepare_context()` и `_compact_runtime()`;
- алгоритмы и пороги сжатия, бюджет и расчёт токенов;
- `branch_memory`, `through_message_id` и постоянная память;
- схемы инструментов и логика выполнения инструментов;
- права доступа к внешним папкам.

## Установка

1. Остановить Workbench.
2. Сделать резервную копию всей рабочей папки и SQLite-базы.
3. Этот патч рассчитан на установленную версию v1.2. Распаковать ZIP в корень `SERGDATA-Workbench-Next` с заменой файлов.
4. Запустить Workbench.

В `.patch-backups/` лежат исходные версии файлов именно из v1.2. Для отката остановить Workbench и вернуть:
- `.patch-backups/execution-continuity-v1.2/main.py` → `main.py`
- `.patch-backups/execution-continuity-v1.2/workbench-agent.py` → `workbench/agent.py`

## Проверки

- `python -m compileall -q main.py workbench` — успешно.
- Целевые тесты checkpoint и внешнего чтения: 9 passed.
- Полный набор на распакованном архиве C с файлами v1.2 и этим исправлением: 267 passed, 15 failed. Эти 15 падений относятся к уже существующим несовпадениям/регрессиям исходного набора C и не были исправлены этим узким патчем; их нужно разбирать отдельно.
- Реальный запрос к LM Studio в этой среде не выполнялся. Поэтому окончательное подтверждение HTTP 400 возможно только после запуска у пользователя.
