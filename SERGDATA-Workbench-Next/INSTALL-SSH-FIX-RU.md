# Установка исправления SERGDATA Workbench

Это обновление поверх существующей установки. Оно исправляет отображение SSH-запросов после ответа модели и усиливает правила, запрещающие модели выдавать текстовое «подтверждаю» за фактический запуск.

## Что исправлено
1. После каждого ответа модели интерфейс обновляет очередь `Выполнение · PowerShell / SSH`. Раньше `send()` обновлял сообщения, статистику и очередь изменений файлов, но не обновлял очередь команд.
2. Модель получает более строгую инструкцию: фразы «подтверждаю» / «запускай» в чате не нажимают кнопку «Выполнить».
3. Добавлены два регрессионных теста.

## Установка
1. Останови Workbench (`Ctrl+C` в окне `start.cmd`).
2. Сделай копию каталога `F:\SERGDATA-Workbench-Next` или хотя бы файлов `static\app.js` и `workbench\agent.py`.
3. Распакуй содержимое архива поверх `F:\SERGDATA-Workbench-Next`, разрешив замену файлов.
4. **Не удаляй и не заменяй** `.env`, `.workbench`, `migration`, пользовательские файлы и SSH-ключи.
5. Запусти `start.cmd`, обнови вкладку Workbench сочетанием `Ctrl+F5`.

## Проверка
1. Отправь модели: `Подключись к FIN и выполни hostname и uptime.`
2. После ответа модели открой панель `Выполнение · PowerShell / SSH`.
3. Карточка SSH-запроса должна появиться сразу, без переключения ветки и перезагрузки страницы.
4. Проверь хост, порт и команду, затем нажми **«Выполнить»**.
5. Дождись терминального статуса и фактического stdout/stderr/exit code.
6. Только после результата модель должна продолжить задачу.

## Важно
Текущий FIN-профиль использует системный OpenSSH и стандартный поиск ключей Windows. `C:\Users\user\.ssh\id_ed25519` — стандартное имя ключа, поэтому OpenSSH найдёт его автоматически, если ключ не зашифрован passphrase либо уже разблокирован через `ssh-agent`. Публичный файл `.pub` указывать не нужно. Host key проверяется строго через `known_hosts`.

Это исправление не выполняет реальное подключение к FIN из среды сборки: оно не имеет доступа к твоему компьютеру, ключу и серверу. Живой SSH-тест нужно провести после установки.
