# Обновление: прозрачность инструментов и файловая диагностика

## Что изменено

- В истории сообщений добавлено поле `metadata` с безопасной миграцией существующей SQLite-базы.
- Каждый вызов инструмента сохраняет имя, безопасный снимок аргументов, статус, длительность, короткий предварительный результат и полный текст результата в сообщении.
- Секретоподобные аргументы маскируются; содержимое записываемых файлов не копируется в журнал действий.
- Интерфейс показывает действие и краткий результат сразу, а аргументы и полный результат раскрываются отдельно.
- Старые сообщения инструментов продолжают отображаться в прежнем формате.
- Список файлов проекта стал рекурсивным (глубина по умолчанию 5, максимум 8) с ограничением вывода.
- Резервные копии и временные файлы скрыты по умолчанию; их можно запросить отдельным флагом.
- Поиск и списки файлов не должны выдавать `.env`, ключи, секретные каталоги и резервные копии.
- ProjectTools больше не создаёт отсутствующий корень проекта автоматически.

## Проверки в изолированной среде

- `python -m pytest -q`: 50 passed.
- `python -m compileall -q .`: успешно.
- `node --check static/app.js`: успешно.
- Проверка браузерного UI не завершена: локальный запуск тестового Chromium заблокирован средой исполнения (`ERR_BLOCKED_BY_ADMINISTRATOR`); сервер также не стартовал в этой среде из-за отсутствующей зависимости `openai`.

## Важно

Это обновление не включает пользовательский экран настроек лимитов LM Studio/Workbench. Оно также не подтверждает интеграцию с реальным LM Studio на Windows. Перед установкой сохраните копию папки Workbench; `.env` и `.workbench` в архив не включены.


## Кроссплатформенная установка и диагностика окружения

- Добавлен `workbench.doctor`: проверяет Python, обязательные/дополнительные Python-пакеты и внешние инструменты без установки и изменения системы.
- Добавлен отдельный `requirements-dev.txt` для pytest, Ruff, BeautifulSoup и html5lib.
- Добавлены `start.sh` и `install-dev.sh` для Ubuntu/Linux, а также `install-dev.ps1` для Windows.
- Обновлён Windows `start.ps1`: проверяет Python 3.12+, коды ошибок установки и запуска, использует локальное `.venv`.
- `.env` и `.workbench` не создаются заново и не перезаписываются этими сценариями.
- Это этап унификации установки и обнаружения окружения; полноценное выполнение Bash-команд агентом и SSH-адаптер ещё не включены.
