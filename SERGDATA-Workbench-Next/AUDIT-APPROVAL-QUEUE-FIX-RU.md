# Исправление очереди подтверждений — 06.11.2026

## Найденные дефекты

1. API очереди фильтровал запросы строго по `branch_id`. При восстановлении соседней ветки UI мог не увидеть ожидающую команду, хотя запись оставалась `pending` в другой ветке того же проекта.
2. Очередь обновлялась в основном после отдельных событий чата; не было постоянной синхронизации в состоянии ожидания подтверждения.
3. `loadExecutionQueue()` менял `waitingForApproval`, но не всегда сразу перерисовывал кнопку отправки.
4. Ошибка API отображалась как простой текст без ясного различия между пустой очередью и неудачным запросом.
5. Кнопка «Обновить очередь» могла молча завершиться, если фоновое обновление уже выполнялось.

## Исправления

- Очередь API теперь определяется проектом активной ветки и возвращает все ожидающие команды этого проекта, независимо от ветки-владельца.
- Каждая карточка показывает проект, задачу и исходную ветку. Сама команда по-прежнему одобряется по исходному ID и продолжает исходный контекст.
- UI опрашивает очередь каждые 2 секунды, пока задача открыта.
- После успешного обновления очередь немедленно синхронизирует `waitingForApproval` и кнопку Compute.
- Ручное обновление показывает toast с количеством ожидающих команд или явной ошибкой.
- Ошибка API больше не маскируется под пустую очередь.
- Если ручное обновление совпало с активным запросом, интерфейс сообщает об этом, а не молчит.

## Сохранённые гарантии

- Само появление команды в очереди не запускает её.
- Запуск по-прежнему идёт только через отдельный POST `/api/execution/{id}/approve`.
- Серверная атомарная смена `pending` -> `running` сохранена.
- Отклонение по-прежнему идёт через отдельный POST `/api/execution/{id}/reject`.
- SSH использует существующий SSH Engine и профиль; обход через PowerShell не добавлялся.
- Изменения сделаны в отдельной копии, исходный архив и рабочая папка не менялись.

## Дополнительная интеграционная доработка — 06.11.2026

- Состояние ожидания подтверждения теперь восстанавливается из постоянной очереди БД при запросе статуса ветки.
- Подтверждение и отклонение вынесены в атомарные методы Store с фиксацией времени и источника решения; повторный клик не может повторно обработать команду.
- Цикл опроса чата синхронизирует очередь подтверждений и состояние кнопки Compute.
- Агент использует строгий адаптер текстовых tool calls в основном цикле и при продолжении после подтверждения/ввода; повтор успешного вызова использует прежний результат вместо повторного запуска.
- Для pytest в Sandbox разрешены только ограниченные аргументы и относительные пути.
- Версия Sandbox теперь увеличивается при каждой записи; повторные чтения/проверки после изменения получают новый ключ повторного вызова.
