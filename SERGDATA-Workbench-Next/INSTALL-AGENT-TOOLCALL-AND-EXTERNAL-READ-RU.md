# SERGDATA Workbench — исправление tool-call и явного чтения другого проекта

Дата сборки: 07.11.2026

## Что исправлено

1. Текстовые вызовы Neohorse `<tool_call>...</tool_call>` разбираются по отдельности. Ошибка в одном блоке больше не отбрасывает соседние корректные вызовы.
2. Для `read_uploaded_file` поддержан узкий совместимый псевдоним `file_id` → `attachment_id`. Если оба параметра переданы с разными значениями, вызов отклоняется.
3. Принятые вызовы выполняются, а модель получает указание исправить только отклонённые. Уже выполненные вызовы повторять не требуется.
4. Транспортные теги `<tool_call>` удаляются из текстовой части нормализованного сообщения перед повторной передачей истории модели.
5. Если формат вызова не исправлен за доступные раунды, пользователь получает явное описание ошибки адаптера, а не сырую транспортную разметку.
6. Добавлены безопасные журнальные маркеры `TOOL_CALL_ADAPTER_OK`, `TOOL_CALL_ADAPTER_REJECTED` и соответствующие маркеры продолжения. Содержимое запросов, аргументы и ответы модели в эти маркеры не записываются.
7. Добавлены `list_registered_project_files` и `read_registered_project_file` для ограниченного чтения другого зарегистрированного проекта. Они доступны только тогда, когда пользователь явно указал **точный корневой путь проекта** в текущем сообщении.

## Как теперь работает внешний путь

Пример запроса:

> Проведи аудит исходников SERGDATA Workbench в `F:\SERGDATA-Workbench-Next`. Найди обработчик вызовов инструментов и прочитай связанные файлы.

Если `F:\SERGDATA-Workbench-Next` уже зарегистрирован как проект Workbench, модель сможет перечислять и читать файлы **внутри этого корня** через новые read-only инструменты. Активный проект и его `PROJECT_ROOT` не меняются.

Ограничения:

- Должен быть указан точный корень зарегистрированного проекта в текущем запросе. Указание только подпапки не выдаёт разрешение на весь проект.
- Если путь не зарегистрирован, доступ будет отклонён. Сначала добавь каталог через управление проектами Workbench или выбери его как проект.
- Чтение использует существующую проверку `ProjectTools`: выход через `..`, переход по symlink за пределы корня и чтение чувствительных файлов запрещены.
- Новые внешние инструменты не умеют записывать файлы, выполнять команды, запускать PowerShell или менять настройки другого проекта.
- Обычные `read_project_file` и `list_project_files` по-прежнему ограничены текущим `PROJECT_ROOT`.
- Запись файлов, Approval Queue, SSH/PowerShell approval и выполнение команд не менялись.

## Установка

1. Останови Workbench через `Ctrl+C` в окне сервера.
2. Сделай резервные копии двух исходников. В PowerShell:

```powershell
$root = 'F:\SERGDATA-Workbench-Next'
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
Copy-Item "$root\workbench\agent.py" "$root\workbench\agent.py.bak-$stamp"
Copy-Item "$root\workbench\tool_call_adapter.py" "$root\workbench\tool_call_adapter.py.bak-$stamp"
```

3. Распакуй архив поверх `F:\SERGDATA-Workbench-Next` с заменой файлов.
4. Не заменяй `.env`, `.workbench`, SQLite, `credentials.dpapi`, SSH-ключи, `known_hosts` и пользовательские загрузки. Их в архиве нет.
5. Запусти Workbench обычным способом через `start.cmd`.

## Проверка после установки

Отправь в **новой задаче или новой ветке** запрос с точным корнем второго зарегистрированного проекта, например:

```text
Проведи read-only аудит проекта F:\SERGDATA-Workbench-Next.
Сначала перечисли его файлы, затем прочитай main.py и workbench/agent.py.
Ничего не изменяй и не запускай.
```

Ожидаемое поведение:

- в логах появляется `TOOL_CALL_ADAPTER_OK ... accepted=N` для текстовых вызовов Neohorse;
- `list_registered_project_files` и `read_registered_project_file` читают файлы внутри указанного зарегистрированного корня;
- `PROJECT_ROOT` активной ветки остаётся прежним;
- инструментальный вызов с `../` или чувствительным файлом отклоняется;
- если один текстовый вызов некорректен, корректные вызовы из того же пакета выполняются, а модель исправляет только отклонённые.

Для проверки локального комплекта тестов из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q workbench tests
```

## Откат

Останови Workbench и верни две резервные копии на исходные имена:

```powershell
Copy-Item "$root\workbench\agent.py.bak-$stamp" "$root\workbench\agent.py" -Force
Copy-Item "$root\workbench\tool_call_adapter.py.bak-$stamp" "$root\workbench\tool_call_adapter.py" -Force
```

Используй фактическое значение `$stamp`, созданное при резервном копировании.
