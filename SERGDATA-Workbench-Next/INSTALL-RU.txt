SERGDATA Workbench + AI-Knowledge — «Добавить только новые файлы» v2
Дата сборки: 07.11.2026

Эта сборка подготовлена ПОВЕРХ варианта ProcessRegistry v1, чтобы не откатывать проверенную кнопку остановки и журнал.

ЧТО МЕНЯЕТСЯ
1) Явно выбранную папку/файл можно индексировать напрямую, даже если она вне F:\AI-Knowledge и не зарегистрирована в sources.json.
2) В диалоге базы знаний появляется отдельная кнопка «Добавить только новые».
3) В этом режиме файл, путь которого уже есть в таблице files, пропускается. Существующие content/modified/chunks/FTS не переписываются.
4) Внешние файлы сохраняются в SQLite под нормализованным абсолютным путём (на Windows формат F:/...). Внутренние пути сохраняют старый относительный формат. Существующие ключи и таблицы не мигрируются.
5) «Индексировать / обновить» сохраняет обычный режим: добавляет новые и обновляет изменившиеся файлы.
6) «Добавить внешний источник» остаётся необязательной регистрацией постоянного каталога. Для разового добавления не нужна.
7) В архив включён workbench/processes.py и main.py/static файлы из ProcessRegistry v1 — чтобы не откатить интеграцию управления задачами, остановки и журнала из этой сборки.

ФАЙЛЫ И ЦЕЛЕВЫЕ ПУТИ
AI-Knowledge/kb.py                         -> F:\AI-Knowledge\kb.py
Workbench/main.py                         -> F:\SERGDATA-Workbench-Next\main.py
Workbench/workbench/processes.py          -> F:\SERGDATA-Workbench-Next\workbench\processes.py
Workbench/static/app.js                   -> F:\SERGDATA-Workbench-Next\static\app.js
Workbench/static/index.html               -> F:\SERGDATA-Workbench-Next\static\index.html

УСТАНОВКА БЕЗ РИСКА ДЛЯ БАЗЫ
1) Остановить Workbench.
2) Сделать резервные копии всех пяти файлов выше.
3) Распаковать архив и скопировать файлы строго по указанным путям.
4) Не заменять и не удалять index\knowledge.db, sources.json, repositories.json, каталоги code/documents, Git-клоны и любые другие файлы.
5) Запустить Workbench, открыть «База знаний», нажать «Папка…», выбрать папку с дополнениями и нажать «Добавить только новые».
6) Проверить журнал операции и число добавленных файлов.

ОТКАТ
Остановить Workbench и вернуть резервные копии пяти файлов. SQLite и файлы источников не мигрируются и не перезаписываются этим патчем.

ПРОВЕРКИ
- py_compile kb.py и main.py: пройдено.
- node --check static/app.js: пройдено.
- UI IDs/handlers: пройдено.
- Тестовая SQLite: внутренний файл и внешний файл из вложенной папки добавлены: пройдено.
- Повторный new-only: существующий файл распознан, ноль новых, старая запись не изменена: пройдено.
- Изменение внешнего файла + повторный new-only: прежнее содержимое в базе сохранено: пройдено.
- Обычный update после изменения: существующая запись обновлена на месте, дубликата нет: пройдено.
- Архив ZIP: проверка целостности пройдена.

ОГРАНИЧЕНИЯ
Тестирование выполнено в изолированной Linux-среде на временной SQLite, не на пользовательской Windows-базе. Перед заменой файлов нужна резервная копия. Проверка на реальном Windows-ПК остаётся обязательной.

Режим «только новые» сравнивает ключ пути, а не хэш содержимого. Если одинаковый файл скопировать под другим именем или в другой каталог, он будет считаться новым. В режиме new-only изменённые по содержимому файлы с уже известным путём не обновляются — для этого есть отдельный режим «Индексировать / обновить».
