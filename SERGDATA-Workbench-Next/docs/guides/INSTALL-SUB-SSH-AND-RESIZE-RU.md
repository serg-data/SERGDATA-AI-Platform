# SERGDATA Workbench — исправление SSH SUB и вертикального ресайзера

Это overlay-обновление для установленной версии Compute Indicator v5. Архив содержит только изменённые исходники, тесты и эту инструкцию.

## Что исправлено

### 1. Парольный SSH-профиль SUB
- Generic `ssh_run_command` теперь ищет точное совпадение `host + username + port` среди сохранённых SSH-профилей.
- Если совпадение найдено, команда автоматически переводится на профильный execution path (`ssh_run_profile_command` semantics), а не на OpenSSH с `BatchMode=yes` и `PasswordAuthentication=no`.
- Для профиля с паролем выполнение использует Paramiko и CredentialBroker; пароль не попадает в argv, историю чата или вывод инструмента.
- Проверка SSH host key остаётся строгой: Paramiko загружает Windows `~/.ssh/known_hosts` и использует RejectPolicy. Неизвестный ключ будет отклонён.
- Если для профильного пароля нет сохранённого credential_ref, Workbench не делает попытку OpenSSH, а возвращает модели точное требование запросить секрет и обновить профиль.
- Если найдено несколько профилей для одного адреса/пользователя/порта, Workbench отказывается выбирать наугад.

### 2. Панель PowerShell / SSH
- Вертикальные разделители стали заметнее и имеют большую активную область.
- Перетаскивание работает через глобальные pointer events, поэтому указатель не теряет drag, если выходит за пределы узкой полосы.
- Высота панели увеличивается перетаскиванием нижнего разделителя вниз.
- Размеры истории и терминала сохраняются в localStorage.
- Высота терминала может занимать до 72% рабочей области; прежнее ограничение 42vh снято.
- Добавлено управление стрелками вверх/вниз при фокусе на разделителе.

### 3. Статус кнопки Compute
- При ожидании защищённого ввода кнопка показывает `🔒 Ввод`, не изображая активную генерацию.
- При ожидании подтверждения SSH кнопка показывает `SSH · Подтвердить`; само подтверждение по-прежнему выполняется отдельной кнопкой «Выполнить» в панели.
- После отправки защищённого ввода интерфейс показывает продолжение работы модели.

## Установка
1. Останови Workbench в окне `start.cmd` сочетанием `Ctrl+C`.
2. Сделай резервную копию каталога `F:\SERGDATA-Workbench-Next`.
3. Распакуй содержимое архива поверх `F:\SERGDATA-Workbench-Next`, разрешив замену файлов.
4. Архив не содержит `.env`, `.workbench`, SQLite, миграционные БД и SSH-ключи. Не удаляй свои данные.
5. Запусти `start.cmd`.
6. Обнови вкладку браузера сочетанием `Ctrl+F5`.

## Проверка SUB
1. В Workbench отправь: `Подключись к SUB через сохранённый SSH-профиль и выполни hostname, id и uptime.`
2. Если профиль запросит секрет, введи пароль только в панели «Защищённый ввод пользователя» и нажми «Отправить ответ».
3. Убедись, что в карточке выполнения указан профиль SUB, а не generic OpenSSH.
4. Проверь host key и нажми «Выполнить».
5. Дождись `completed`/`failed`, stdout, stderr и exit code.

Если увидишь `RejectPolicy` / unknown host key — не отключай проверку. Сначала проверь fingerprint SUB отдельно и добавь подтверждённый ключ в `C:\Users\user\.ssh\known_hosts`.

## Проверка изменения высоты
- Наведи мышь на горизонтальную полоску между историей и панелью выполнения или между панелью выполнения и полем ввода.
- Полоска должна подсветиться и расшириться.
- Для увеличения панели PowerShell/SSH перетащи нижний разделитель вниз.
- Размер должен сохраниться после перезагрузки страницы.
- При фокусе на полоске можно использовать стрелки вверх/вниз.
