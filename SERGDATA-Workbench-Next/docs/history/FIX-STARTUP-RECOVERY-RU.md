# Исправление медленного запуска Workbench

## Причина

В `main.py` обработчик FastAPI `lifespan` синхронно ожидал:
- `agent.resume_execution(...)` для сохранённых результатов PowerShell/SSH;
- `agent.resume_input_request(...)` для сохранённых ответов пользовательского ввода.

Оба метода продолжают диалог через локальную LLM. Поэтому при медленном/занятом LM Studio запуск Uvicorn не доходил до `Application startup complete`, хотя сам HTTP-сервер уже был готов к работе.

## Исправление

- Восстановление сохранённых продолжений перенесено в отдельную фоновую asyncio-задачу, запускаемую после завершения критической части startup.
- `lifespan` больше не ожидает ответа LM Studio.
- Продолжения по-прежнему выполняются последовательно и через `run_tracked_agent_task`, поэтому состояние активности ветки остаётся видимым.
- При штатном завершении сервера фоновая задача отменяется и дожидается завершения отмены.
- `CancelledError` не превращается в обычную ошибку.
- Восстанавливаются только сохранённые результаты уже завершённых операций и отправленный пользовательский ввод. Команды PowerShell/SSH повторно не запускаются.
- Ошибки чтения очереди фонового восстановления записываются в журнал, а не маскируются под ошибку запуска сервера.

## Цветной вывод pytest

Добавлен `pytest.ini` с `--color=yes`: успешные тесты отображаются зелёным, ошибки — красным (если терминал поддерживает ANSI-цвета).

## Проверки в этой среде

- `compileall`: успешно.
- `node --check static/app.js`: успешно.
- Структурный регрессионный тест startup: 1 passed (зелёный).
- Полный pytest не запускался: в текущей среде отсутствует зависимость `openai`, необходимая для импорта Agent. Это ограничение тестовой среды, а не результат тестов проекта.
