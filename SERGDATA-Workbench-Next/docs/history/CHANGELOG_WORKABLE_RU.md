# Изменения SERGDATA Workbench Next — IDE foundation

## Добавлено
- Управление несколькими проектами через список проектов и создание проекта по существующей папке.
- Переключение проекта с независимым списком задач.
- Создание задач в выбранном проекте.

- Отдельная постоянная память проекта и задачи; обе включаются в контекст соответствующей ветки.
- Ручное сохранение контрольной точки: старые сообщения сворачиваются в память ветки, последние 8 остаются полной историей.

- Валидация project root и запрет выхода файловых инструментов за пределы корня проекта.

## Учёт токенов и контроль контекста (2 ноября 2026)
- Добавлена предварительная токенизация через LM Studio Python SDK: применяются шаблон чата и токенизатор именно загруженной модели. Схема инструментов и её служебная обвязка показаны как отдельная оценка, а не объявлены точным значением.
- Размер активного контекстного окна запрашивается у уже загруженной модели через `get_context_length()`. Перед SDK-вызовом проверяется `state=loaded`, чтобы не инициировать JIT-загрузку модели ради статистики. Fallback: `loaded_context_length` из REST API, если доступно; иначе `CONTEXT_LIMIT` из `.env`. Максимальная ёмкость модели не подменяет активный лимит.
- Порог автоматического сжатия рассчитывается относительно фактического доступного лимита модели, если SDK его сообщает.
- Каждое обращение к LM Studio записывается отдельно: обычный вызов, запрос tool call, сжатие памяти и финализация после ошибки. API `usage` хранится отдельно от оценки текущего контекста.
- Исправлен учёт расходов при ответвлении: видимая история показывает унаследованный расход до точки fork отдельно от расходов новой ветки; последующие запросы родителя не включаются.
- Добавлен индикатор неучтённых обращений, если LM Studio не вернула полный `usage`. Последнее пользовательское обращение суммирует все его API-вызовы; неполная сумма помечается отдельно. Старые агрегированные данные не удаляются и не дублируются.
- UI показывает оценку следующего запроса, рабочий лимит, запас с резервом под ответ, агрегированный фактический расход последнего пользовательского обращения и отдельный журнал внутренних вызовов.
- SQLite обновляется добавлением таблицы `llm_calls` и nullable-колонки `usage.turn_message_id`; существующие данные и вложения сохраняются.
- Добавлена зависимость `lmstudio>=1.5.0`; при недоступности SDK остаётся явный fallback на `cl100k_base`.

## Совместимость запросов с шаблонами LM Studio (2 ноября 2026)
- Исправлена причина ошибки `Multi-part or consecutive system prompts are not supported`: системная инструкция, память проекта, задачи и ветки теперь объединяются в одно начальное сообщение `system`.
- Результаты инструментов, сохранённые в старой истории, передаются отдельными помеченными сообщениями `user` в хронологическом порядке. Внутри текущего цикла реальные tool calls/tool results сохраняют штатный формат OpenAI tools.
- Инструкция после остановки повторного/ошибочного вызова инструмента больше не добавляется как новое системное сообщение в середину диалога.
- Улучшена диагностика HTTP-ошибок LM Studio: при наличии ответа сервера Workbench показывает ограниченный фрагмент тела ошибки, а не только `BadRequestError: Error code: 400`.
- Добавлены регрессионные тесты на единственное начальное сообщение `system` и безопасную передачу результатов прошлых инструментов.
- Проверки: `python -m pytest -q` — 21 тест; `compileall` и `node --check` — успешно. Реальный вызов LM Studio в среде сборки не выполнялся.
