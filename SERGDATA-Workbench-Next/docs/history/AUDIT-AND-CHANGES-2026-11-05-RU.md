# Аудит и изменения SERGDATA Workbench — 05.11.2026

## Что изменено
- Ужесточена проверка путей при выборочном копировании файлов в Sandbox.
- Проверяются исходные компоненты пути до `resolve()`, поэтому символьная ссылка внутри проекта не маскируется разрешением пути.
- Запрещены абсолютные пути, `.`/`..`, пустые компоненты и чувствительные пути.
- При ошибке выборочного копирования частично созданная песочница удаляется.
- Добавлен регрессионный тест на symlink traversal и отсутствие частичной песочницы.

## Проверки
- `pytest -q tests/test_sandbox.py`: 7 passed.
- `python -m compileall -q workbench`: успешно.
- Полный `pytest -q`: 184 passed, 2 failed.
- Оба падения относятся к `ProcessRegistry`/callback и возникают из-за таймингов фоновых процессов в этой среде: тест ожидает завершение за 0.03–2 секунды, но процесс остаётся в `running`/не завершает callback вовремя. Это реальные непрошедшие тесты; они не объявляются успешными.
- Ruff в окружении отсутствует.

## Ограничения, которые не устранены
- Текущий Sandbox остаётся файловой копией, а не изоляцией ОС.
- `run_check()` запускает pytest/compile/ruff как обычные процессы хоста. Это НЕ безопасная среда для недоверенного кода.
- В текущем окружении нельзя подтвердить Windows Sandbox, Windows Job Objects, Docker Desktop или поведение Windows-процессов.
- Linux/VPS исполнение через SSH требует отдельной проверки на целевом сервере.
- `passwall-auto-failover.sh` не запускался.

## Безопасность архива
Из дистрибутива исключены `.env`, `.workbench` (включая локальную БД и DPAPI-хранилище), `.git`, кэши Python и pytest. Исходный архив и исходная рабочая папка не изменялись.
