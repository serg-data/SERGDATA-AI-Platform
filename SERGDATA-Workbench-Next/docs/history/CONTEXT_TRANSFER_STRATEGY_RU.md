# Перенос контекста — SERGDATA Workbench

## Назначение

Новая задача получает отдельный контекст разговора. Ветки внутри исходной задачи не считаются независимыми лимитами контекста: при переносе можно выбрать, какой объём знаний собрать в компактный технический пакет.

## Режимы переноса

1. **Только текущая ветка (`branch`)** — история выбранной ветки с её унаследованной историей, её память и связанные сведения о вложениях. Самый экономный режим.
2. **Вся задача (`task`)** — память задачи, память и доступная история всех веток этой задачи. Истории, унаследованные через fork, дедуплицируются по ID сообщения.
3. **Задача + проект (`project`)** — режим `task`, плюс сводные сведения других задач и веток того же проекта и постоянная память проекта. Память проекта остаётся общей и не копируется в новую задачу второй раз.

Во всех режимах LM Studio формирует компактное инженерное резюме. Новая задача создаётся только после успешного непустого ответа модели. Создание задачи и сохранение её handoff-памяти выполняются одной транзакцией SQLite.

## Что сохраняется в handoff

- цель и подтверждённый контекст;
- архитектура и важные пути/имена;
- принятые решения и причины;
- выполненные изменения и подтверждённые проверки;
- ошибки, ограничения и незавершённая работа;
- следующий конкретный шаг;
- источник переноса и выбранный режим.

Вложения не копируются физически. При успешном переносе Workbench создаёт явные записи доступа `task_attachment_access` для новой задачи в той же SQLite-транзакции, что и задача/память. Поэтому новая задача может видеть, искать, читать и прикладывать эти файлы, не меняя исходную привязку и не раскрывая их другим задачам или проектам. Удаление исходного вложения удаляет и выданные ссылки доступа. Перед чтением модель всё равно должна проверить доступность файла; бинарные вложения без индексируемого текста доступны для скачивания, но не превращаются автоматически в текст.

## Защита от слишком большого проекта

Для режима `project` вводятся ограничения объёма: не более 40 задач и 60 веток в одном сборе, не более 52 000 символов истории для модели. Если данных больше, API возвращает счётчики пропусков, а в резюме добавляется предупреждение, что не все ветки переданы полностью. Для очень крупного проекта следует переносить конкретную задачу или затем дополнительно читать нужные сведения из проектной базы.

## Пороговые предупреждения

- до 60% — обычная работа;
- 60–74% — предупреждение о росте контекста;
- 75–84% — предложение подготовить перенос;
- от 85% — рекомендация продолжить в новой задаче.

Оценка контекста предварительная, если токенизатор или LM Studio не предоставили точные данные. Автоматическое сжатие старой истории в агенте остаётся отдельным механизмом и не заменяет перенос в новую задачу.

## Сохранность исходных данных

Перенос не удаляет и не изменяет сообщения исходной задачи, её ветки и вложения. Новая задача создаётся в том же проекте. Файлы `.env`, каталог `.workbench` и база SQLite не входят в обновляющий ZIP и не должны заменяться при установке.

## Проверки этой версии

- тесты сбора контекста по трём областям;
- тесты передачи доступа к вложениям без копирования файлов и без утечки в другие задачи/проекты;
- проверка изоляции разных проектов;
- проверка дедупликации общей истории веток;
- проверка атомарного создания новой задачи с handoff-памятью;
- Python compileall;
- JavaScript syntax check.

Реальный вызов LM Studio и графический запуск на Windows должны быть дополнительно проверены в пользовательском окружении.
