# SERGDATA Workbench — диагностика 502 и обновление подсветки

## Изменённые файлы

- `main.py` — добавлен диагностический ID для ошибок `/api/chat`; журналируются тип исключения, upstream HTTP status и traceback frames. Содержимое prompt, ответа модели и тело upstream-ошибки в журнал не записываются.
- `static/app.js` — после ошибки `/api/chat`, если серверная генерация уже завершена, Workbench заново загружает сохранённую историю, статистику и очередь инструментов. `loadMessages()` теперь возвращает загруженный список сообщений.
- `static/index.html` — изменён cache-busting URL `app.js`, чтобы браузер запросил новый JavaScript вместо использования прежнего cache key.
- `tests/test_chat_rendering_regressions.py` и `tests/test_chat_cancel.py` — регрессионные проверки.

## Установка

1. Остановить Workbench.
2. Сделать резервные копии `main.py`, `static/app.js`, `static/index.html`.
3. Распаковать архив в корень проекта, заменив эти три файла.
4. Запустить Workbench.
5. В браузере выполнить `Ctrl+F5`. Новый URL скрипта: `app.js?v=20261106-chat-refresh-highlight3`.

## Проверка после установки

- Обычный запрос должен отображаться без задержки после завершения.
- Если `/api/chat` вернёт 502 после успешных вызовов инструментов, история перечитается автоматически, и сохранённые результаты останутся видны.
- В серверном журнале найти `CHAT_API_FAILURE id=...` по диагностическому ID из сообщения браузера. Журнал намеренно не содержит содержимое prompt/ответа.
- Повторно проверить SH-код с кавычками и комментариями: `class="tok-string">` и `class="tok-comment">` не должны появляться как буквальный текст.
- Проверить копирование из блока кода.

## Откат

Остановить Workbench и вернуть три резервных файла на исходные места. Затем запустить Workbench и выполнить `Ctrl+F5`.

## Что этим патчем не меняется

Не изменяются `workbench/agent.py`, `workbench/tools.py`, `workbench/execution.py`, `workbench/db.py`, API очереди подтверждений, переходы статусов команд и SQLite. Подсветка `highlightCode()` не переписывалась: исправление cache key обеспечивает фактическую загрузку уже имеющейся исправленной реализации.

## Границы тестирования

Локальные тесты проверяют синтаксис JavaScript, HTML-результат `renderMarkdown()`, код ветки 502, обновление истории и регрессии очереди. Реальная связка с LM Studio/Neohorse и визуальный DOM браузера требуют контрольного запуска на машине пользователя.
