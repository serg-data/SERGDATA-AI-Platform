# SERGDATA Workbench — отчёт v6: SUB SSH, панель выполнения и состояния Compute

## Подтверждённые дефекты по пользовательским скриншотам

1. SUB — парольный профиль. После защищённого ввода модель вызвала `ssh_run_command`, который создавал generic SSH execution. В `workbench/ssh.py` этот путь запускает OpenSSH с `BatchMode=yes` и `PasswordAuthentication=no`, поэтому парольный вход невозможен. На скриншоте подтверждена ошибка `Permission denied (publickey,password)`.
2. Вертикальная панель PowerShell/SSH не регулировалась для пользователя. Исходный JS использовал локальные pointer listeners на узком handle, а CSS ограничивал высоту терминала. Исправлен drag lifecycle и лимиты, добавлено сохранение.
3. Compute не отличал активную генерацию от ожидания защищённого ввода/подтверждения. Добавлены отдельные состояния.

## Изменения в этой сборке

- `workbench/ssh.py`: добавлен `find_matching_profile()` для точного сопоставления адреса, пользователя и порта; неоднозначное сопоставление отклоняется.
- `workbench/agent.py`: `ssh_run_command` сначала проверяет зарегистрированный профиль. При совпадении направляет команду в `__SERGDATA_PROFILE_EXEC_V1__`, чтобы парольный профиль прошёл через CredentialBroker + Paramiko. OpenSSH generic используется только для незарегистрированных целей.
- `workbench/agent.py`: обновлена системная инструкция — зарегистрированные адреса должны использовать профильный инструмент.
- `static/app.js`: добавлены UI-состояния ожидания защищённого ввода и подтверждения SSH; после отправки секрета отображается возобновление модели.
- `static/app.js`: вертикальный ресайзер переведён на глобальные pointer events, сохраняет высоту, поддерживает клавиатуру.
- `static/style.css`: увеличена активная область разделителя, снят старый лимит высоты панели, добавлены стили статусов.
- Добавлены тесты маршрутизации SSH и UI состояния/ресайзера.

## Проверки

- `node --check static/app.js`: OK.
- `python -m compileall -q workbench`: OK.
- Набор целевых тестов: 31 passed.
- Полный тестовый набор не объявляется полностью пройденным: в первом прогоне два теста `ProcessRegistry` не уложились в короткие таймауты среды; повторный запуск одного теста Agent не собрался из-за отсутствующей зависимости `openai` в текущей среде аудита.
- Не выполнялись: реальный SSH к SUB, проверка пароля, browser E2E ресайзера, проверка на Windows DPAPI/LM Studio.

## Безопасность

- Секрет не добавляется в командную строку процесса.
- Парольный профиль использует Paramiko + CredentialBroker.
- Host key проверяется через known_hosts с RejectPolicy; обход проверки не добавлялся.
- Для неизвестного host key соединение будет отклонено.
- Архив не включает `.env`, `.workbench`, SQLite, миграционные базы, кэш, пользовательские загрузки и SSH-ключи.
