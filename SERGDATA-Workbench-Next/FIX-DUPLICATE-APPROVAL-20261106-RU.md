# Исправление повторного подтверждения команды

## Подтверждённая проблема
В обработчике POST /api/execution/{eid}/approve отказ атомарного claim генерировал HTTPException(409), который перехватывался общим except Exception. Это приводило к попытке перевести уже запущенное выполнение в failed и преждевременно возобновить модель.

## Исправление
HTTPException теперь повторно выбрасывается отдельно до общего обработчика ошибок. Повторный запрос получает 409 без изменения статуса выполняющейся команды и без запуска resume. Остальные ошибки запуска по-прежнему обрабатываются прежним путём.

## Проверки
Добавлены два регрессионных теста: атомарный повторный claim не меняет running; маршрут подтверждения отдельно пропускает HTTPException. Регрессионные тесты прошли. `compileall` прошёл. Полный набор: **216 passed** (`python -m pytest -q -p no:cacheprovider`, exit code 0, 17.50 s).

## Дополнительная проверка

Проверена цепочка хранения результата: процессный callback и резервный путь `/api/processes/{jid}` используют `finish_execution_once`, а `resume_execution` использует атомарный `claim_execution_resume`. Это защищает от двойной передачи результата модели. При этом успешность реального SSH/Windows PowerShell/LM Studio требует отдельного smoke-теста в пользовательской среде.

## Ограничения
Реальные SSH, PowerShell на Windows и LM Studio не тестировались в этой среде. Этот патч исправляет конкретную гонку повторного подтверждения, но не является доказательством устранения всех причин отсутствия автоматического продолжения модели.
