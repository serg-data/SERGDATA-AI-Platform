SERGDATA / AI-Knowledge — исправление инкрементального обновления v2

Что исправлено
--------------
1. update-knowledge.ps1 больше не использует git pull --ff-only как единственный
   способ синхронизации существующего репозитория.
2. Для существующих репозиториев выполняется git fetch --prune origin — Git
   получает недостающие объекты, а папка репозитория повторно не клонируется.
3. Если локальные коммиты уже представлены в upstream (git cherry показывает '-'),
   перед синхронизацией создаётся резервная ветка backup/pre-sync-... и выполняется
   безопасное git reset --keep. Если локальные коммиты уникальны, создаётся такая
   же резервная ветка и upstream объединяется merge-коммитом. При конфликте merge
   отменяется, исходная ветка сохраняется.
4. После Git-синхронизации формируется точный список изменённых и удалённых путей.
   Индексатор не обходит весь каталог code и не сканирует все 35 тысяч файлов.
5. kb.py получил --paths-file. Он обновляет только перечисленные файлы, удаляет
   удалённые/переименованные файлы из files, chunks, search и chunk_search.
6. Документы релизов синхронизируются прежним release_sync.py. В индексатор передаётся
   только каталог documents/releases дополнительно к Git-изменениям; неизменённые
   release-документы пропускаются по mtime и наличию chunks. Git-изменения помечаются
   как force: они перечитываются даже при совпадении mtime после checkout.
7. Манифест pending-index-changes.json сохраняется до успешного завершения индексации.
   Если индексатор завершится с ошибкой или процесс будет остановлен, следующий запуск
   повторит незавершённые изменения. Повторная обработка безопасна.
8. База index/knowledge.db не пересоздаётся, не очищается и не VACUUM-ится.

Установка
---------
1. Останови текущий запуск обновления AI-Knowledge, если он выполняется.
2. Сделай копии двух файлов в F:\AI-Knowledge:
      kb.py
      update-knowledge.ps1
3. Распакуй содержимое ZIP прямо в F:\AI-Knowledge с заменой этих двух файлов.
   Структура архива:
      kb.py
      update-knowledge.ps1
      README-INCREMENTAL-FIX-v2-RU.txt
4. Не удаляй и не перемещай папку index, файл knowledge.db или папку code.
5. Запусти update-knowledge.ps1 обычным способом из своей рабочей среды.

Как понять, что исправление сработало
-------------------------------------
В update-knowledge.log должны появиться строки:
  ТОЧЕЧНАЯ ИНДЕКСАЦИЯ
  Изменённых путей: N; удалённых: M
  Индексация завершена ... Обновлено файлов: ...

Вместо прежнего полного этапа «ПЕРЕИНДЕКСАЦИЯ» должен запускаться
«ТОЧЕЧНАЯ ИНДЕКСАЦИЯ».
Если Git-конфликт не удаётся разрешить автоматически, соответствующий репозиторий
будет пропущен с объяснением. Его история и файлы останутся на месте; резервная
ветка будет иметь имя backup/pre-sync-... . Это безопасный отказ, а не потеря данных.

Важно о проверке
----------------
Проверено в изолированной тестовой копии:
- первичная индексация тестовых документов;
- изменение одного файла при сохранении другого;
- удаление файла из files/chunks/FTS5;
- поиск нового содержимого после точечного обновления;
- принудительное обновление Git-изменённого файла при сохранённом прежнем mtime;
- Git-сценарии эквивалентного локального коммита и уникального локального коммита
  (backup ref + reset --keep / merge upstream).

В этой среде нет Windows PowerShell 5.1 и доступа к локальным репозиториям
F:\AI-Knowledge, поэтому фактический запуск полного PowerShell-сценария на твоём
компьютере не выдаётся за уже выполненный тест. Первый запуск следует проверить
по update-knowledge.log. База знаний при этом не затрагивается пересозданием.
