SERGDATA Workbench — Git Doctor для раздела «База знаний»
Версия: v2 (диагностический этап)

ВАЖНО
Это диагностическая версия. Она НЕ выполняет автоматическое исправление Git и не меняет содержимое репозиториев. Восстановление индекса будет добавлено отдельным проверенным этапом после подтверждения диагноза на реальном systemd.

РАСПОЛОЖЕНИЕ
Кнопка «Git Doctor · диагностика» добавлена непосредственно в окно «База знаний», рядом с «Git-репозитории». Правая колонка Git не изменялась намеренно: её Stage/Unstage/Commit/Push/Diff и API не переписывались.

ЧТО ДЕЛАЕТ
- Загружает список только из AI-Knowledge/repositories.json через существующий API.
- Показывает только обнаруженные локальные клоны внутри AI-Knowledge/code.
- Запускает read-only диагностику выбранного клона.
- Показывает путь, ветку, HEAD, porcelain-v2 status и подозрительные записи удаления.
- Записывает событие диагностики в существующий журнал операций базы знаний.

ЧЕГО НЕ ДЕЛАЕТ
- Не запускает git add/restore/reset/checkout/pull/fetch.
- Не удаляет untracked-файлы.
- Не меняет index, refs, рабочие файлы, БД знаний или pending-git-changes.json.
- Не затрагивает внешние источники.

УСТАНОВКА
1. Остановить Workbench.
2. Сделать резервную копию текущей папки Workbench.
3. Распаковать архив поверх корня Workbench с сохранением структуры.
4. Запустить Workbench → «База знаний» → «Git Doctor · диагностика».
5. Выбрать systemd и нажать «Проверить».
6. Передать полный текст диагностики.

ПРОВЕРКИ В СРЕДЕ СБОРКИ
- python -m compileall -q workbench — OK
- node --check workbench/static/app.js — OK
- pytest tests/test_git_manager.py — 5 passed

ОГРАНИЧЕНИЕ
Это патч интерфейса и read-only диагностики, не финальный автоматический ремонт. Не называйте репозиторий исправленным до проверки статуса после отдельной процедуры восстановления.
