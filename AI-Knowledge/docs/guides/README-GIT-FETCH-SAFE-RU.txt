SERGDATA / AI-Knowledge — безопасный fetch при локальных изменениях

ЧТО ИСПРАВЛЕНО
Раньше git_incremental.py проверял грязную рабочую копию ДО git fetch и сразу
пропускал репозиторий. Теперь сначала выполняется fetch настроенной upstream-ветки.
Fetch обновляет remote-tracking refs и Git objects, но не меняет рабочие файлы,
индекс или текущую ветку. После fetch скрипт проверяет локальное состояние.

ЕСЛИ РАБОЧАЯ КОПИЯ ЧИСТАЯ
Дальше действует прежняя логика обновления: fast-forward либо безопасная попытка
слияния с резервной ссылкой для старого HEAD. Конфликты по-прежнему блокируют
изменение ветки.

ЕСЛИ ЕСТЬ ЛОКАЛЬНЫЕ/НЕОТСЛЕЖИВАЕМЫЕ ФАЙЛЫ
Скрипт сообщает, что fetch выполнен, показывает число локальных и удалённых
коммитов и откладывает применение обновления. Никакие локальные файлы не
удаляются и не перезаписываются.

УСТАНОВКА
1. Остановить Workbench и все процессы синхронизации AI-Knowledge.
2. Сделать копию F:\AI-Knowledge\git_incremental.py.
3. Из архива заменить только git_incremental.py в корне F:\AI-Knowledge.
4. Запустить полную синхронизацию. Проверить лог для passwall2/sing-box/3x-ui.

НЕ ДЕЛАТЬ
- Не выполнять git reset --hard, git clean, rebase или ручное удаление файлов.
- Этот патч НЕ чинит локальные конфликты и не делает автоматическое слияние грязных
  рабочих копий. Для этого нужен отдельный Git Doctor с просмотром/карантином.

ПРОВЕРКА
Патч проверен py_compile и тестом во временных bare/clone репозиториях:
- upstream получил новый коммит;
- рабочая копия содержала локальное изменение и untracked файл;
- fetch обновил origin/main;
- локальный файл и untracked файл сохранились побайтно;
- применение обновления было безопасно отложено.
Проверка выполнена в Linux-контейнере, не на пользовательской Windows-машине.
