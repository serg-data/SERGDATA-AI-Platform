SERGDATA AI-KNOWLEDGE — ИНКРЕМЕНТАЛЬНОЕ ОБНОВЛЕНИЕ v3
====================================================

ЧТО ИСПРАВЛЕНО
--------------
1. Существующие Git-репозитории больше не клонируются заново.
   Для них выполняется git fetch --no-tags только настроенной upstream-ветки.
   Git получает недостающие объекты; уже имеющиеся объекты повторно не скачиваются.

2. Изменения определяются сравнением старого и нового commit:
   добавленные/изменённые/переименованные/удалённые пути.

3. Индексатор получает JSON-манифест точных путей. Полный обход 35 тыс. файлов
   после обновления Git не запускается.

4. Изменённые файлы принудительно перечитываются, даже если mtime совпал.
   Удалённые, пустые и переставшие индексироваться файлы удаляются из files,
   chunks и соответствующих FTS5-таблиц.

5. Release Notes также добавляют в тот же манифест только реально изменённые
   документы. Сетевой опрос Release Notes сохраняет собственный интервал.

6. Манифест удаляется только после успешной точечной индексации. При ошибке он
   остаётся в index/pending-git-changes.json и будет обработан при следующем запуске.

7. Локальные коммиты защищены refs/backup/ai-knowledge/<repo>/<old-head>.
   Fast-forward выполняется только после проверки ancestry. Если ветки разошлись,
   patch-equivalent локальные коммиты синхронизируются с сохранением backup ref;
   уникальные локальные коммиты объединяются только если git merge-tree заранее
   подтвердил отсутствие конфликтов. Конфликтующие/грязные рабочие копии не меняются.

8. Не используются git reset --hard и git clean. Нет автоматического удаления,
   повторного клонирования или перезаписи локальных файлов существующего репозитория.

УСТАНОВКА
---------
1. Останови обновление AI-Knowledge и Workbench.
2. Сделай резервные копии четырёх текущих файлов:
   F:\AI-Knowledge\kb.py
   F:\AI-Knowledge\update-knowledge.ps1
   F:\AI-Knowledge\release_sync.py
   (нового файла git_incremental.py пока нет)
3. Распакуй содержимое архива прямо в F:\AI-Knowledge, с заменой трёх файлов
   и добавлением git_incremental.py.
4. НЕ удаляй и НЕ заменяй:
   index\knowledge.db
   index\release_sync_state.json
   repositories.json
   папку code\
   папку documents\
   внешние источники и их данные.
5. Сначала запускай обычным способом update-knowledge.ps1 из F:\AI-Knowledge.
   Можно запускать и через Workbench: параметры -BasePath/-PythonPath/-NoPause
   теперь поддерживаются.
6. После завершения пришли update-knowledge.log целиком или последние 300 строк.

ВАЖНЫЕ ОГРАНИЧЕНИЯ И ЗАЩИТА
--------------------------
- Если в репозитории есть незакоммиченные tracked или untracked изменения, он
  пропускается без изменения рабочей копии. Сначала нужно отдельно разобраться
  с этими файлами. Это намеренно безопаснее автоматического stash/reset.
- Если локальных коммитов больше 20, автоматическое слияние блокируется.
- Если merge-tree обнаруживает конфликт, Git-ветка и рабочие файлы остаются
  на прежнем состоянии; причина попадёт в лог. Никакой конфликт не разрешается
  автоматически выбором ours/theirs.
- Для man-pages и systemd сохранены защитные проверки специфических Windows
  sparse-checkout. При нарушении условий скрипт сообщает об этом и не скачивает
  репозиторий заново.
- Первое клонирование отсутствующего репозитория неизбежно скачивает его
  начальное содержимое. Для уже существующих репозиториев используется fetch.
- Внешние источники не добавляются в Git-манифест и не сканируются этим обновлением.

ПРОВЕРКИ В ЭТОЙ СБОРКЕ
---------------------
Проверены на временных локальных bare Git origin и отдельной тестовой SQLite/FTS5:
- fast-forward/fetch и точный список изменённых файлов;
- добавление, изменение и удаление файлов в SQLite/FTS5;
- повторный запуск без изменений не создаёт манифест;
- patch-equivalent divergent commits синхронизируются с backup ref;
- бесконфликтное расхождение объединяется с сохранением обеих историй;
- конфликтующее слияние не меняет HEAD и рабочий файл;
- грязная рабочая копия сохраняется и пропускается.

Python-файлы прошли py_compile. Синтаксис PowerShell 5.1 проверен статически,
но запуск на Windows пользователя ещё не выполнялся. Поэтому после установки
нужна проверка реального лога; не запускай полную ручную индексацию.
