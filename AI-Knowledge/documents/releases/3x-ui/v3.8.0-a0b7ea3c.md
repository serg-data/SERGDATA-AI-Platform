## Описание релиза

## 🚀 TUIC v5, AmneziaWG outbounds, Discord notifications, Xray-core v26.9.9 & hardened installs

- 🚀 **TUIC v5 inbounds** — a bundled `tuic-server` sidecar terminates TUIC and relays into Xray, so TUIC clients get per-client stats, routing and quotas like every other protocol, with `tuic://` share links, Clash output and their own QR tab.
- 🛰️ **AmneziaWG everywhere** — AmneziaWG is now an outbound protocol too, Clash subscriptions can emit AmneziaWG proxies, multi-server NordLynx outbounds arrive alongside, and the embedded tunnel picked up a dozen relay, MTU, keying, locking and throughput fixes.
- 💬 **Discord notifications** — a Discord bot service mirrors the Telegram alerts with its own settings tab, while the Telegram bot gained ownership checks, HTML escaping, mutex-safe state and panic containment.
- ⚙️ **Xray-core v26.9.9** — two core bumps, with one-time template migrations for the keys the new core refuses or deprecates and a follow of the `udpHop` → `udphop` mask move.
- 🔐 **Hardened installs** — release archives ship SHA-256 sums that `install.sh`/`update.sh` verify, geo databases are checked against published digests, the management script comes from the tag you installed, the SQLite store is owner-only and fresh panels get random subscription paths.
- 📡 **Subscription overhaul** — client-app integration headers and curated routing presets, routing profiles and DNS servers baked into JSON subscriptions, a legacy Clash endpoint, a dummy info/status node, opt-in month-end expiry display and an HWID slot-status endpoint.
- 🖧 **Multi-node correctness** — client edits fan out to every node at once, a node can no longer resurrect a deleted client or claim another inbound's client, and a newly selected inbound is imported instead of swept.
- 🧩 **Panel UX** — a global Ctrl+K command palette, linked host remarks in the inbound list, a Reality scan-candidate setting, geodata source presets, a routing-rule comment field and a Generate button for tunnel preshared keys.
- 🔗 **Share-link fidelity** — imports keep mKCP seed and headerType, Shadowsocks TLS params and obfuscation, VMess certificate checks and `vcn`; Clash output drops nodes it cannot express and emits bare hosts.

## ⚠️ Before you upgrade

### Action required
- A wrong or disabled API Bearer token now answers **401**, not 404 — **do this:** update any script that reads 404 as "auth failed". A request with no `Authorization` header is still masked as 404, and a wrong `webBasePath` still 404s.
- REALITY no longer applies a built-in minimum client version when `minClientVer` is empty; empty now means **no minimum** — **do this:** if you were relying on the implicit 26.3.27 floor, set the field explicitly on each Reality inbound.
- A hysteria2 **outbound** stored before this release still carries the old `quicParams.udpHop` key, which the new core silently drops — port hopping just stops — **do this:** re-import that outbound's share link, which now emits the new `udphop` mask. Inbounds are unaffected; the key was never read server-side, and they still advertise their `mport` range.
- TUIC v5 needs the `tuic-server` sidecar, which release archives, the Docker image and `install.sh` place **next to the panel binary** — it is no longer copied to `/usr/local/bin`, where the panel never read it — **do this:** if you dropped your own `tuic-server` into `/usr/local/bin` for the panel, move it beside the panel binary instead.
- `install.sh`/`update.sh` verify the archive against its published **SHA-256** sidecar and abort on a mismatch or on any fetch failure other than a 404 (which older tags return and which only warns) — **do this:** if your installs go through a mirror, cache or TLS-terminating proxy, make sure it serves `<asset>.sha256` alongside the archive.
- `install.sh`/`update.sh` now take `x-ui.sh` and the service units from the **same release tag** as the archive instead of always from `main` — **do this:** if you forked or pinned those files, re-point them at the tag. The menu falls back to `main` with a visible notice when a tag publishes no script; `dev-latest` still tracks `main`.
- JSON subscriptions bind their local SOCKS/HTTP inbounds to **127.0.0.1** instead of `0.0.0.0` — **do this:** if a client on your fleet deliberately reached that proxy from another machine, it has to run on the same device now.

### Automatic — no action needed
- Stored Xray templates are rewritten once for the keys the new core refuses or deprecates: outbound `proxySettings.tag` → `streamSettings.sockopt.dialerProxy`, `addressPortStrategy` dropped from freedom outbounds, freedom `domainStrategy` moved into `sockopt`, and the DNS outbound's legacy `nonIPQuery`/`blockTypes` converted into the three rules the core's own legacy builder produced. Either of the first two kept the core from starting at all after the upgrade; the rest only logged a deprecation warning on every config load.
- The SQLite directory becomes **0700** and the database plus its `-wal`/`-shm` files **0600** on the next start — they held client UUIDs, Reality private keys and the admin password hash under the default umask. A chmod the panel cannot perform is logged and skipped, not fatal. PostgreSQL deployments are untouched.
- A legacy MTProto custom share address becomes a **Host**, unless a Host already advertises the same address. Old imports stay compatible.
- An inbound `subSortIndex` of 0 or omitted is lifted to 1; explicitly negative values are now preserved so a primary inbound can sort ahead of the default without renumbering its peers.
- Growing a node's inbound selection re-arms adoption, so the inbound you just ticked is imported on the next sync rather than deleted from the node by the delete sweep. The trade: an inbound deleted on the master while that node was unreachable is re-imported instead of swept if you grow the selection during the same outage.
- A **fresh** panel database seeds cryptographically random base64 / JSON / Clash subscription paths, and a factory reset regenerates them. Existing settings are preserved.
- Re-running the IP-limit setup writes the fail2ban backend override to `/etc/fail2ban/jail.d/3x-ipl-backend.conf` instead of editing the packaged `jail.conf`, so a fail2ban upgrade can no longer drop it. It is removed with the other `3x-ipl` files on uninstall.

### 🔐 Security

- An Xray log path smuggled in under a different key case (`"Access": "/tmp/pwn.log"`) escaped the panel's confinement, because the core matches those fields case-insensitively while the panel matched them exactly — reopening the arbitrary root-owned file write that GHSA-jm48-m3rr-9hgg closed. Every case variant is now folded onto the canonical key, and a canonical value wins over a smuggled one ([`f9de0226`](https://github.com/MHSanaei/3x-ui/commit/f9de0226))
- The JSON subscription's local SOCKS and HTTP inbounds carried no listen address, so every client that ran the profile verbatim opened an **unauthenticated proxy on 0.0.0.0**; both are bound to loopback now ([#6418](https://github.com/MHSanaei/3x-ui/pull/6418)) @FZ1010
- Appending `?view=raw` to a JSON or Clash subscription URL returned before the HWID gate ran, handing out a complete config no matter how many device slots were already used ([`f17e4684`](https://github.com/MHSanaei/3x-ui/commit/f17e4684))
- A non-admin tapping a subscription, links or QR button in Telegram was served whatever email the button carried — and those keyboards outlive the chat they were sent to, through group chats, forwards, and a client whose Telegram id was later revoked. The callback is now authorized against the caller's own client record ([#6489](https://github.com/MHSanaei/3x-ui/pull/6489)) @BlindMaster24
- The Telegram admin list was replaced under a mutex but read without one by the report cron, the backup job and every incoming callback, so an admin check could iterate past the backing array of a slice header caught mid-replacement ([#6491](https://github.com/MHSanaei/3x-ui/pull/6491)) @BlindMaster24
- Tapping a stale inbound keyboard in Telegram could panic on a row deleted between two reads, and the callback handler ran on a bare goroutine with no `recover()` — **that panic killed the whole panel process**. The row is fetched once and all three handler paths now sit behind a recover barrier ([#6442](https://github.com/MHSanaei/3x-ui/pull/6442)) @BlindMaster24
- A node reporting a client email that collides with a master-only client overwrote that client's UUID, and the master then rebuilt its own Xray config with the node-supplied credential — locking the real user out. A reported client whose record belongs only to other inbounds is now refused ([`a31fa9ab`](https://github.com/MHSanaei/3x-ui/commit/a31fa9ab))
- A node snapshot captured before a bulk delete could resurrect the deleted clients, restoring access you had revoked ([#6382](https://github.com/MHSanaei/3x-ui/pull/6382)) @mvanhorn
- The SQLite store was created world-readable under the default umask while holding client UUIDs, Reality private keys and the admin password hash; the directory, the database, its side files and the `migrate-db` dump are now owner-only ([#6390](https://github.com/MHSanaei/3x-ui/pull/6390)) @rokokol
- A freshly created panel database seeds random subscription paths instead of the fixed defaults everyone could guess ([#6375](https://github.com/MHSanaei/3x-ui/pull/6375)) @rokokol
- Release archives now publish a SHA-256 sidecar that `install.sh` and `update.sh` verify before extracting as root — TLS protected the transport, not the bytes, and a swapped or truncated asset was installed unchecked. Any fetch failure on the sidecar other than a 404 aborts, so dropping the 90-byte request is not a way around the check ([#6393](https://github.com/MHSanaei/3x-ui/pull/6393)) @rokokol
- Downloaded geo databases are verified against the `.sha256sum` all three upstreams publish and staged in a temporary folder first, so a substituted or corrupted file installs nothing instead of taking the core down at its next start ([#6404](https://github.com/MHSanaei/3x-ui/pull/6404)) @rokokol
- The installer pinned the panel archive to a release tag but always pulled `x-ui.sh`, `x-ui.rc` and the service units from `main`, so a reviewed or digest-pinned installer still ran unreviewed code and two installs of the same tag could differ. They now come from the tag being installed ([#6391](https://github.com/MHSanaei/3x-ui/pull/6391)) @rokokol
- The node heartbeat probe decoded a node-controlled status body with no size limit while probing up to 32 nodes at once, so the allocation was dictated by the peer — the last uncapped read of node data, now capped at 1 MiB ([`ab422953`](https://github.com/MHSanaei/3x-ui/commit/ab422953))
- One host sending a single datagram from each of 4096 source ports filled a TUIC inbound's relay table and locked every new client out of it for up to two minutes; a full table now evicts the flow last seen longest ago ([`5815254f`](https://github.com/MHSanaei/3x-ui/commit/5815254f))

**The ones most likely to have been biting you**

- An inbound saved with security `tls` and a certificate row holding neither a file path nor inline content took the **entire** config build down with it, every other inbound included; the credentials are validated on both sides of the wire now ([#6429](https://github.com/MHSanaei/3x-ui/pull/6429)) @duqigit

- Two admins running the Telegram add-client wizard at the same time wrote into one shared draft, so whichever step ran last decided the email, the limits and the attached inbounds of a client the other chat went on to create ([#6499](https://github.com/MHSanaei/3x-ui/pull/6499)) @BlindMaster24
