# SERGDATA Index Cleaner

Небольшая автономная Windows-утилита для точечного удаления индексированных путей из существующей базы `AI-Knowledge`.

## Что умеет

- Показывает индексированные пути и количество фрагментов.
- Первично читает базу в фоновом потоке, затем хранит полученные пути и счётчики в памяти до явного обновления или смены базы.
- Не сканирует целиком FTS5-таблицы при построении списка — использует основные таблицы `files` и `chunks`.
- В таблицах отображает результаты порциями по 50 строк; фильтр ищет по полному списку в памяти и не обращается к SQLite. Очистка папки охватывает все пути, а не только показанные строки.
- Раздел **«Папки и репозитории»** позволяет выбрать папку, репозиторий или несколько папок и удалить все индексированные пути внутри них.
- Раздел **«Отдельные файлы»** позволяет удалить один или несколько выбранных путей.
- Показывает, существует ли исходный файл/каталог на диске.
- Перед удалением создаёт резервную копию SQLite через Backup API.
- В одной транзакции удаляет выбранные пути из `files`, `chunks`, `search` и `chunk_search`.
- Проверяет FTS5 и `PRAGMA integrity_check` после удаления.
- Не удаляет исходные файлы и папки.

## Установка

1. Распакуйте папку `SERGDATA-Index-Cleaner` внутрь каталога `knowledge`, рядом с `kb.py` и папкой `index`.
2. Убедитесь, что база находится по пути `knowledge\index\knowledge.db`.
3. Остановите индексацию и закройте SERGDATA Workbench.
4. Запустите `SERGDATA-Index-Cleaner\Run_Index_Cleaner.bat`.

Утилита автоматически ищет корень AI-Knowledge вверх от своей папки. Если база расположена в другом месте, используйте кнопку **«Выбрать базу…»**.

## Использование

1. После выбора базы дождитесь первичного чтения.
2. После загрузки ввод фильтра, очистка фильтра, переключение вкладок и выбор строк используют данные в памяти — повторного чтения SQLite при этих действиях нет.
3. Полное чтение выполняется только при первом открытии, выборе другой базы, нажатии **«Обновить список»** и после успешной очистки.
4. Выберите строки (поддерживается множественный выбор).
5. Нажмите **«Удалить выбранное из индекса»**.
6. Проверьте предупреждение и подтвердите операцию.
7. После завершения сохраните путь к резервной копии, показанный в окне результата.

Резервные копии создаются в `index\cleaner-backups\`.

## Важные ограничения и безопасность

- Перед удалением обязательно остановите все процессы индексации и закройте Workbench. Утилита не может надёжно определить все внешние процессы, которые могут писать в SQLite.
- Удаляются только точные выбранные пути и их записи в четырёх таблицах. Остальные источники не затрагиваются.
- Внешние пути `@external/<source-id>/...` отображаются и могут быть очищены выборочно. Для определения их наличия используется `sources.json`.
- Удаление из индекса не удаляет исходные файлы, папки, Git-репозитории или записи реестра `repositories.json`.
- Для полного удаления репозитория из индекса выберите его каталог в `code/` на вкладке **«Папки и репозитории»**.
- Если проверка FTS5 или SQLite завершается ошибкой, транзакция очистки откатывается. Созданная резервная копия остаётся на диске.
- Программа рассчитана на текущую схему AI-Knowledge: `files`, `chunks`, `search`, `chunk_search`, где у каждой таблицы есть поле `path`.
- Для запуска нужен Python 3 с Tkinter (обычно входит в установщик Python для Windows). Дополнительные pip-пакеты не нужны.

## Изменения v0.1.2

- Исправлено зависание окна при чтении большой базы: загрузка выполняется в отдельном потоке.
- Путь выбранной базы отображается сразу, до начала чтения.
- Убрана агрегация по FTS5-таблицам при построении списка; это снижает объём тяжёлых операций.
- Построение дерева папок переведено на линейную агрегацию.
- Список отдельных файлов ограничен первыми 3 000 отображаемыми строками для сохранения отзывчивости; фильтр применяется ко всему загруженному списку.

## Проверка

Код проверен на синтаксис и протестирован на временной SQLite-базе с той же структурой таблиц: выборочное удаление очистило записи из четырёх таблиц, сохранило соседние пути, создало резервную копию и прошло `integrity_check`. Реальная пользовательская база в тесте не открывалась и не изменялась.


### Работа с большими базами (v0.1.3)

- Фильтр срабатывает после короткой паузы ввода, а не на каждую клавишу.
- Агрегация папок и проверка их наличия выполняются в фоновом потоке.
- В таблицах одновременно отображается не более 1 500 строк; фильтр ищет по полному списку, а не только по видимым строкам.
- Во вкладке отдельных файлов состояние отображается как «В индексе»: массовые проверки наличия каждого файла на диске убраны, чтобы не блокировать интерфейс.
- Ограничение отображения не ограничивает очистку: при выборе папки удаляются все индексированные пути внутри неё.


## Изменения v0.1.4

- Фильтрация работает только с уже загруженными объектами в памяти; SQL-запросы из обработчиков фильтра отсутствуют.
- Отрисовка Treeview выполняется пакетами по 50 строк с короткими паузами, чтобы Tkinter не блокировал окно при обновлении списка.
- Новый ввод отменяет незавершённую отрисовку предыдущего фильтра.
- Полное чтение SQLite оставлено только для первичной загрузки, выбора другой базы, явной команды «Обновить список» и обновления после очистки.
