# SERGDATA Workbench

Локальная рабочая среда для разработки и сопровождения проектов с помощью локальной LLM, инструментов работы с файлами, управляемых операций и Git.

> Workbench рассчитан на локальный запуск на компьютере пользователя. По умолчанию веб-сервер доступен только через `127.0.0.1`.

## Возможности

### Проекты и рабочий контекст

- Регистрация нескольких существующих папок как отдельных проектов.
- Проекты, задачи и независимые ветки диалога.
- История сообщений, статистика токенов и постоянная память проекта/ветки.
- Контрольные точки и экспорт контекста для переноса работы.

### Локальная LLM

- Подключение к LM Studio через OpenAI-compatible API.
- Настройка адреса API, модели и параметров контекста через `.env`.
- Вызов инструментов в рамках агентного цикла с ограничением числа шагов.

### Работа с файлами и безопасное выполнение

- Просмотр и чтение файлов проекта.
- Загрузка и хранение вложений в рабочем хранилище Workbench.
- Предварительный запрос и подтверждение изменений файлов пользователем.
- Отдельные запросы подтверждения для команд и операций, требующих разрешения.
- SSH-профили и удалённые операции с проверкой host key.

### Сравнение папок и выборочный выпуск изменений

Workbench умеет сравнивать две отдельные папки проектов по относительным путям и SHA-256:

- **Добавленные** — присутствуют в исходной папке, отсутствуют в целевой.
- **Изменённые** — содержимое отличается.
- **Удалённые** — присутствуют в целевой папке, отсутствуют в исходной.

Пользователь выбирает конкретные файлы. Сначала формируется план выпуска, при этом целевая папка ещё не меняется. Перед применением Workbench повторно проверяет хеши, чтобы не перенести файлы, изменившиеся после сравнения. При применении сохраняется резервная копия заменяемых файлов; при ошибке выполняется откат уже затронутых файлов.

Служебные каталоги и потенциально секретные файлы исключаются из сравнения и выпуска, в том числе `.git`, `.workbench`, виртуальные окружения, `.env*`, ключи и локальные базы данных. Ограничения размера и количества файлов заданы в `workbench/release_manager.py`.

### Git и публикация

- Проверка состояния репозитория и просмотр diff.
- Инициализация Git, выборочное Stage/Unstage и Commit.
- Просмотр веток и истории коммитов.
- Настройка remote и операции Fetch/Pull/Push.
- Операции Git выполняются в корне выбранного зарегистрированного проекта.

Перед Pull/Push приложение проверяет наличие незакоммиченных изменений. Для публикации нужен настроенный remote и доступ к Git-серверу.

## Требования

- Windows 10/11 или Linux.
- Python 3.12 или новее.
- Git — для Git-функций.
- LM Studio с загруженной моделью и включённым Local Server — для работы с локальной LLM.
- Доступ к сети нужен для первоначальной установки Python-зависимостей и для тех внешних сервисов, которые пользователь сам подключает.

Основные Python-зависимости перечислены в `requirements.txt`. Инструменты разработки и тестирования — отдельно в `requirements-dev.txt`.

## Быстрый запуск в Windows

1. Распакуйте проект в постоянную папку, например `F:\SERGDATA-Workbench-Next`.
2. Установите Python 3.12+ и Git.
3. Запустите `start.cmd`.
4. При первом запуске скрипт создаст `.venv`, установит зависимости и выполнит диагностику окружения.
5. Если `.env` отсутствует, он будет создан из `.env.example`. Проверьте настройки LM Studio и, если используете Knowledge MCP, пути `KB_SERVER`, `KB_CWD` и `KB_PYTHON`.
6. Откройте в браузере `http://127.0.0.1:8787`.

Для ручного запуска после установки:

```powershell
.\.venv\Scripts\python.exe main.py
```

## Запуск в Linux

Создайте виртуальное окружение, установите зависимости и запустите приложение:

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

Откройте `http://127.0.0.1:8787`.

## Настройки

Основные параметры задаются в `.env`. Шаблон находится в `.env.example`.

| Переменная | Назначение |
|---|---|
| `LM_BASE_URL` | OpenAI-compatible API локальной модели, обычно `http://127.0.0.1:1234/v1` для LM Studio |
| `LM_API_KEY` | Значение API-ключа, ожидаемое локальным сервером |
| `LM_MODEL` | Имя модели для API-запросов |
| `KB_ENABLED` | Включение интеграции Knowledge MCP |
| `KB_SERVER` | Путь к серверному скрипту Knowledge MCP |
| `KB_CWD` | Рабочая папка Knowledge MCP |
| `KB_PYTHON` | Команда или путь к Python для Knowledge MCP |
| `CONTEXT_LIMIT` | Лимит контекста, используемый Workbench |
| `MAX_TOOL_ROUNDS` | Ограничение числа агентных шагов |
| `HOST` | Адрес привязки сервера; удалённый bind без отдельной защищённой архитектуры запрещён |
| `PORT` | Порт веб-интерфейса, по умолчанию `8787` |

## Данные и резервное копирование

- Локальная база Workbench и пользовательские данные хранятся в `.workbench/`.
- Виртуальное окружение хранится в `.venv/`.
- Локальные настройки и секреты хранятся в `.env` и других локальных хранилищах.
- Эти каталоги и файлы исключены из Git через `.gitignore`.

Перед обновлением или переносом установки остановите Workbench и сделайте резервную копию `.workbench/` и `.env`. Не публикуйте `.env`, DPAPI-файлы, SSH-ключи, токены, пароли, локальные базы и пользовательские вложения.

## Проверки разработчика

Установка дополнительных средств тестирования:

```powershell
python -m pip install -r requirements-dev.txt
```

Запуск тестов:

```powershell
python -m pytest -q
```

Для диагностики зависимостей и внешних инструментов:

```powershell
python -m workbench.doctor
```

## Безопасность

Workbench содержит инструменты чтения/изменения файлов, выполнения подтверждаемых операций и SSH-доступа. Не открывайте его веб-интерфейс в интернет или локальную сеть через `HOST=0.0.0.0` без отдельной аутентифицированной и проверенной схемы удалённого доступа. Перед публикацией изменений проверяйте список Stage и содержимое коммита.

## Структура проекта

- `main.py` — FastAPI-приложение и HTTP API.
- `workbench/` — модули конфигурации, базы данных, Git, сравнения/выпуска, инструментов и агентного цикла.
- `static/` — веб-интерфейс.
- `requirements.txt` — основные зависимости.
- `requirements-dev.txt` — зависимости разработки и тестирования.
- `start.cmd`, `start.ps1`, `start.sh` — сценарии запуска.
